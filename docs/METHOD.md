# 视频处理方法与局限

## 处理过程

1. 逐帧解码 RGB 视频，输入数组的轴为 `[y, x, channel]`。
2. 使用半开像素区间裁剪，默认 `x=[100, 600)`、`y=[0, 600)`。
3. 沿水平方向 `x` 对 RGB 三个通道分别求算术平均。每帧保留 `[height, 3]` 的剖面，而非保留整段解码视频。
4. 堆叠为 `[frame, height, 3]`，除以 255 后交换时间和高度轴，形成 `[height, frame, 3]` 的图像。
5. 第一帧时间为 0，随后按 `frame_index / fps` 标定时间。垂直轴为裁剪区域内从上向下增加的像素坐标。

水平均值、默认裁剪区域与 RGB 归一化方法沿用原 `pre_process()` 及主绘图逻辑。八个本地视频已与原全视频裁剪、均值算法逐元素核对，最大绝对差均为 0；5 项合成检查均通过。逐帧处理旨在减少内存占用，尚未实测运行速度或进程峰值内存。

这八个视频均为 30 fps、173 帧。默认元数据帧率与 `--fps 30` 两次绘图都成功，输出像素一致。以上验证只覆盖已有八个视频与合成用例，不代表其他拍摄条件均已验证。

## 与原代码的差异

| 项目 | 原代码 | 当前候选代码 |
| --- | --- | --- |
| 输入路径 | 本机固定绝对路径 | 必填 `--data-dir` |
| 读取 | 一次解码并保留全部帧 | 逐帧读取，仅保留平均剖面 |
| 坐标 | 独立 `select()` 方法的 x/y 次序与主流程不一致 | 删除未使用辅助方法，裁剪统一为 `[y, x, channel]` |
| 时间轴 | 固定以每 30 帧标 1 秒，刻度止于约 172 帧 | 使用各视频元数据帧率与实际帧数，可用 `--fps 30` 指定标定 |
| 垂直轴 | 未说明物理单位 | 标注为裁剪区域内像素 |
| 结果保存 | 当前目录固定 `p.png`，可能覆盖 | 输出路径可指定，默认时间戳，拒绝覆盖已有文件 |
| 辅助试验 | 未使用的 `test_plot()` 引用未定义变量 | 删除该试验入口及未使用的查看方法，保留一个正式入口 |

## 解释边界

- RGB 水平均值反映图像颜色分布。尚未做光照校正、染料浓度标定、羽流边界识别、质量通量估计或夹卷率计算。
- 垂直像素尚未换算为物理长度。图中标注的 `v` 单位沿用已有图件与代码，具体物理定义待实验记录补充。
- 元数据帧率描述视频的播放时间。原始拍摄是否包含慢放、变速或剪辑尚未核实，因此播放时间与物理实验时间的关系仍待确认。对于可变帧率视频，当前等间隔模型也需进一步核对。
- 两张保存的实验图件保留原内容。本地已用优化代码生成新图，RGB 均值已核对一致，但新旧图件排版不同；这些处理验证不构成夹卷率等定量结论的证据。
- 仓库不包含子视频，公开仓库本身只能展示既有图件和汇总视频；完整复现需要本地持有对应八个输入视频。
